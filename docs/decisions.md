# Решения (ADR)

Формат: контекст → решение → последствия.

## ADR-001. Отдельный git-репозиторий внутри `cnv/`

**Контекст.** `cnv/` лежит под `/home/dmr`, а домашний каталог — сам по себе git-репо
(дотфайлы). Без своего репо весь проект попал бы в дотфайлы.

**Решение.** `git init` внутри `cnv/`. Вложенный репозиторий, родительский видит его как
неотслеживаемый каталог.

**Последствия.** Коммиты проекта изолированы. Remote отсутствует — пуша не будет,
пока не появится и пока его не одобрят.

## ADR-002. Пакетный менеджер — npm

**Контекст.** В системе есть npm 12 и pnpm 11. Упаковка через electron-builder.

**Решение.** npm.

**Последствия.** electron-builder корректно резолвит зависимости из плоского
`node_modules`; с pnpm пришлось бы держать `.npmrc` с `node-linker=hoisted`. Ставим
чуть дольше, зато без сюрпризов на этапе упаковки.

## ADR-003. Имя приложения

**Контекст.** ТЗ требует вынести рабочее название в одну константу.

**Решение.** `cnv` — по имени каталога. Константа `APP_NAME` в `src/shared/app.ts`,
из неё же берутся `productName` для electron-builder и заголовок окна.

**Последствия.** Переименование — правка одной строки плюс `package.json`.

## ADR-004. Живые веб-страницы — `<webview>`, несмотря на предупреждение Electron

**Контекст.** ТЗ требует `<webview>`. Дока Electron 44 открывается блоком `## Warning`:
«We currently recommend to not use the `webview` tag», туториал web-embeds добавляет,
что доступность API в будущих версиях не гарантируется. Формального deprecation, RFC и
даты удаления нет; в breaking-changes 33→44 записей об удалении тоже нет. Спайк
(`docs/spike-results.md`, пп. 1–5) показал, что всё требуемое работает: масштабирование
CSS-трансформом, хит-тест на любом zoom, обход `X-Frame-Options`, оверлей, `capturePage`.
Альтернатив нет: `iframe` режется `X-Frame-Options`, `WebContentsView` — нативный слой
поверх окна, он не масштабируется CSS и не даёт рисовать DOM поверх себя.

**Решение.** Используем `<webview>`. Всю работу с ним прячем за менеджером веб-нод
(`src/renderer/web/`) и типом ноды в реестре, чтобы замена механизма означала правку
одного модуля, а не всего холста.

**Последствия.** Функциональность есть сегодня. Риск «выпилят в Electron 45+» принят и
локализован. Обновление мажора Electron требует прогона спайка заново.

## ADR-005. Wayland: никаких `ozone-platform-hint`

**Контекст.** ТЗ предлагает `app.commandLine.appendSwitch('ozone-platform-hint','auto')`.
Переменная `ELECTRON_OZONE_PLATFORM_HINT` удалена в Electron 38, сам флаг
`--ozone-platform-hint` выпилен из Chromium 140 — дефолтом `--ozone-platform` стал `auto`.
Спайк подтвердил: без единого флага приложение поднимается нативным Wayland-клиентом
(нет в `xlsclients`), с `--ozone-platform=x11` — под XWayland.

**Решение.** Не ставим никаких ozone-флагов. Для отладки под X11 —
`--ozone-platform=x11` руками. В `createMainWindow` держим подстраховку от открытого
бага electron#48859 (`ready-to-show` на Wayland иногда не приходит): принудительный
`show()` через 2.5 с.

**Последствия.** Меньше кода, поведение совпадает с дефолтом Chromium. При откате на
Electron < 38 понадобится вернуть флаг.

## ADR-006. Лимит живых webview остаётся, но не ради памяти

**Контекст.** ТЗ исходит из того, что каждый `<webview>` — отдельный renderer-процесс.
Замер (`spike-results.md`, п. 6) это опроверг: пять гостей с разными origin получили
один и тот же `getOSProcessId()`, количество процессов не растёт с 1 до 10 нод. Первый
гость стоит ~290 МБ (в основном GPU-процесс), каждый следующий — 3–5 МБ.

**Решение.** Лимит живых webview (по умолчанию 6) и переход в `snapshot` сохраняем, но
обосновываем иначе: общий renderer-процесс означает, что CPU, раскладка и растеризация
у всех гостей общие, а зависший или упавший гость роняет всех разом. Память —
второстепенный аргумент.

**Последствия.** Поведение по ТЗ не меняется. Порог по памяти в настройки не выносим —
нечего настраивать; крутилки — лимит живых, порог zoom и таймаут вне viewport.

## ADR-007. Строгий CSP только в собранном приложении

**Контекст.** ТЗ требует CSP без `unsafe-eval`. В dev Vite вставляет inline-скрипт
react-refresh, из-за чего `script-src 'self'` ломает разработку.

**Решение.** CSP вставляется мета-тегом плагином `cnv-csp` с `apply: 'build'` —
то есть только в продакшен-сборку. В dev CSP нет.

**Последствия.** Итоговое приложение под строгим CSP; расхождение dev и prod проверяется
e2e-тестами, которые гоняются по собранному `out/`.

## ADR-008. Сборка renderer минифицируется явно

**Контекст.** electron-vite 5 по умолчанию отдал неминифицированный бандл renderer
(665 КБ).

**Решение.** `renderer.build.minify: 'esbuild'`, sourcemap выключен.

**Последствия.** 237 КБ вместо 665 КБ.

## ADR-009. Версии: vite 7, а не 8

**Контекст.** На момент старта npm отдаёт vite 8.3.1, @vitejs/plugin-react 6.1.1,
TypeScript 7.0.2. Но `electron-vite@5.0.0` объявляет peer `vite: ^5 || ^6 || ^7`, а
`@vitejs/plugin-react@6` требует `vite: ^8`. Пара несовместима.

**Решение.** vite 7.3.6 + @vitejs/plugin-react 5.2.0 + electron-vite 5.0.0 + vitest 4.1.11
(peer `vite ^6.4 || ^7 || ^8`). TypeScript 5.9.3, а не 7.0.2: вокруг TS 7 ещё нет
устоявшегося тулинга (`@electron-toolkit/tsconfig`, typescript-eslint). ESLint 9, не 10.
Все версии в `package.json` зафиксированы точно, без `^`.

**Последствия.** Пересмотреть, когда electron-vite объявит поддержку vite 8.

## ADR-010. Состояние вида — в sidecar, а не в `.canvas` ⟶ ЗАМЕНЁН ADR-017

**Контекст.** ТЗ разрешает выбрать между дополнительными полями с префиксом и
sidecar-файлом, потребовав сначала проверить, что Obsidian не ломается на лишних полях.
Проверил по-настоящему: поднял установленный Obsidian с `--remote-debugging-port`,
подцепился по CDP, открыл канвас с мусорными полями в ноде, в ребре и в корне, сдвинул
ноду его собственным API и дал ему сохранить файл (`scripts/obsidian-roundtrip.mjs`).
**Всё уцелело:** `x-cnv` на ноде, `totallyUnknownField` на ноде, `customEdgeField` на
ребре, `rootLevelJunk` в корне.

**Решение.** Всё равно sidecar `.<name>.canvas.state.json`. Совместимость тут ни при чём:
камера меняется на каждый pan, и держать её в `.canvas` — значит дёргать автосохранение,
watcher и git-диффы при простом разглядывании холста. В sidecar едут камера, текущая
страница PDF и zoom внутри веб-страницы.

**Последствия.** Решение прожило до перехода на модель «один файл» (ADR-014): требование
владельца «файл 1» сильнее аргумента про частоту записи. См. ADR-017.

## ADR-011. История — пополевые патчи, а не снимки документа

**Контекст.** ТЗ требует двух вещей сразу: каждое действие пользователя — одна
транзакция (7.6), и навигация внутри веб-страницы в историю холста не попадает,
хотя `url` ноды в документе при этом обновляется (5.3). Снимок документа на каждую
запись истории это ломает: undo чужой правки откатил бы и `url`, которого никто не трогал.

**Решение.** Транзакция хранит пополевые патчи `{ before, after }` только для тех
сущностей, что реально изменились, плюс порядок массивов, если он менялся. Undo
накладывает `before` на текущее состояние — поля, которых транзакция не касалась,
остаются как есть. Навигация идёт через `mutateSilent` (в историю не пишет).
Диффы считаются на `commit` по структурному разделению (`===`), immer не нужен.
Глубина истории — 200 записей, выделение вне истории.

**Последствия.** Покрыто тестом «откат не затирает поля, которых транзакция не касалась».
Цена — на каждой транзакции проход по массивам нод и рёбер; для целевых 500 нод это
сравнение ссылок, не данных.

## ADR-012. Сериализация повторяет формат Obsidian байт в байт

**Контекст.** Файл, открытый и сохранённый без изменений, должен быть семантически
идентичен. Но если он ещё и побайтово идентичен, то канвас, который правят и в cnv, и в
Obsidian, не даёт мусорных диффов в git.

**Решение.** Писатель повторяет раскладку Obsidian: табы, одна нода в строке, компактный
JSON внутри объекта, порядок ключей как у него, без завершающего перевода строки.
Порядок снят с файла, который Obsidian создал сам (`scripts/obsidian-make-fixture.mjs`
→ `tests/fixtures/obsidian-authored.canvas`). Тест сравнивает `serialize(parse(fixture))`
с исходником побайтово.

**Последствия.** Одна тонкость, которую видно только на живом файле: у `group` метка
пишется ПОСЛЕ геометрии, а у `text`/`file`/`link` их поля идут ДО неё. ТЗ описывает
правило иначе; победил реальный Obsidian.

## ADR-013. Относительные пути в markdown — от корня workspace

**Контекст.** В `![](attachments/x.png)` внутри текстовой ноды путь можно трактовать
относительно канваса или относительно корня workspace. ТЗ не уточняет.

**Решение.** От корня workspace — так же, как трактуются пути в самих нодах JSON Canvas.
Одно правило на весь документ, никакого «зависит от места».

**Последствия.** `DOMPurify` по умолчанию режет схему `canvas-file:`, поэтому
`ALLOWED_URI_REGEXP` расширен ровно на неё; остальные схемы остаются запрещёнными.

## ADR-014. Один канвас в одном файле вместо workspace

**Контекст.** ТЗ 4.3 требовало открывать папку-workspace, держать список `.canvas`-файлов
в боковой панели, создавать/переименовывать/удалять их и переключаться табами. Владелец
проекта по ходу работы уточнил задачу: нужен **скретчпад** — «открыл, поработал, закрыл»,
без проектов и без управления кучей файлов.

**Решение.** Приложение всегда открывает ровно один канвас:

- путь берётся из CLI-аргумента, иначе из настроек, иначе
  `<Документы>/cnv/scratchpad.canvas`; файла нет — создаётся пустой;
- корень для вложений и протокола `canvas-file://` — папка этого файла;
- боковая панель, создание/переименование/удаление файлов и табы убраны;
- сменить файл хранения можно командой «Хранить канвас в файле…» (`Ctrl+Shift+O`).

**Последствия.** Из ТЗ выпадают пункты 4.3 (панель файлов) и 3.12 (табы) — это
сознательное сужение по требованию владельца, а не пропуск. Формат файла, round-trip,
вложения и совместимость с Obsidian не меняются: канвас остаётся обычным JSON Canvas,
который можно открыть в Obsidian.

## ADR-015. Сохранение: debounce, период и флаш при закрытии

**Контекст.** Скретчпад не должен терять написанное, даже если его закрыли сразу после
правки. Один debounce этого не гарантирует: правки могут идти непрерывно, а закрытие
окна не ждёт асинхронную запись.

**Решение.** Три уровня:

1. debounce ~1 с после последней правки;
2. страховочная запись раз в 30 с, если документ грязный (debounce мог всё время
   сбрасываться);
3. при закрытии окна main перехватывает `close`, дёргает в renderer `window.__cnvFlush()`
   и ждёт его (с потолком 2 с), и только потом закрывает окно.

**Последствия.** Покрыто e2e: правка, немедленное закрытие окна, чтение файла с диска.

## ADR-016. Гостевые страницы живут как в настоящем браузере

**Контекст.** Требование владельца: авторизации в веб-нодах не должны слетать после
перезапуска. Само по себе `partition="persist:web"` это уже даёт, но две вещи ломали
картину.

**Решение.**

1. **User-agent гостя** очищается от токенов `Electron/…` и `cnv/…`. Часть провайдеров
   входа (в первую очередь Google) отказывает браузерам, которых не узнаёт. У сессии
   самого приложения UA остаётся честным.
2. **Разрешения.** Раньше `setPermissionCheckHandler` глушил вообще всё, включая
   `storage-access` и `persistent-storage`, — а на них держатся сценарии входа со
   сторонними куками. Теперь есть явный белый список (storage-access,
   top-level-storage-access, persistent-storage, clipboard-sanitized-write, fullscreen,
   pointerLock, keyboardLock); камера, микрофон, геолокация, нотификации и остальное
   по-прежнему отклоняются, как требует ТЗ 2.4.

**Последствия.** Покрыто e2e: кука и `localStorage`, записанные в госте, переживают
полный перезапуск приложения; UA гостя не содержит `Electron`, UA приложения — содержит.

## ADR-017. Состояние вида переехало внутрь `.canvas` (заменяет ADR-010)

**Контекст.** ADR-010 держал камеру и текущую страницу PDF в соседнем
`.<name>.canvas.state.json`, чтобы pan не дёргал сам канвас. После перехода на скретчпад
(ADR-014) владелец сформулировал требование прямо: «весь канвас сериализуется в
**единственный** файл». Sidecar этому противоречит, а совместимость с Obsidian тут ни при
чём — round-trip посторонних полей проверен на живом Obsidian ещё в ADR-010.

**Решение.** Камера, текущая страница PDF и zoom внутри веб-страницы лежат в самом
документе, в корневом поле `x-cnv`. Пишутся через `mutateSilent`, то есть мимо истории
холста, и не чаще раза в секунду после остановки камеры. Состояние исчезнувших нод
вычищается при записи. Sidecar-модуль удалён.

**Последствия.** Файл у приложения ровно один — это проверяется e2e (в папке канваса нет
ничего похожего на `.state.json`). Цена, о которой владелец знал, выбирая вариант: канвас
перезаписывается и от простого разглядывания холста, и в git будут диффы от движения
камеры. Ноды и рёбра при этом не трогаются — отдельный тест сравнивает их с исходником
после «сохранить без правок».

## ADR-018. Одиночный перевод строки в карточке остаётся переводом строки

**Контекст.** markdown по спецификации склеивает одиночные `\n` в один абзац. В
карточке-заметке это выглядит как потеря текста: написал три строки — увидел одну.

**Решение.** `markdown-it` с `breaks: true`. Полноценный markdown (заголовки, списки,
код, ссылки) остаётся, а одиночный перевод строки рендерится как `<br>`.

**Последствия.** Файл `.canvas` не меняется — правится только рендер. Вариант «весь текст
в `<pre>`» отвергнут: он убил бы разметку, которой требует ТЗ 6.1.

## ADR-019. Масштаб интерфейса — через zoom-фактор окна

**Контекст.** На 4K-экране интерфейс мелкий. Нужен выбор ×1 / ×1.25 / ×1.5 / ×1.75 / ×2.
В Electron это традиционно больное место, вариантов три:

- `--force-device-scale-factor` — требует перезапуска и лезет в аргументы Chromium;
- CSS (`rem`, `zoom` на `:root`) — не достаёт до гостевых `<webview>`, а весь наш CSS
  написан в px, то есть это переписывание стилей целиком;
- `webContents.setZoomFactor` — меняет размер CSS-пикселя для страницы.

**Решение.** `setZoomFactor` на окне. Вся координатная математика (`getBoundingClientRect`,
`clientX`, `visibleRect`) живёт в CSS-пикселях и остаётся согласованной, поэтому хит-тест,
snapping и drag не трогаем вообще. Масштаб применяется при создании окна, на каждом
`did-finish-load` (в dev перезагрузка страницы его сбрасывает) и при смене настройки.

Отдельно — **гости**. `<webview>` это отдельный WebContents со своим zoom: при масштабе
×1.5 его бокс становится в полтора раза больше физически, а страница внутри продолжает
верстаться в 1.0 и показывает в полтора раза больше содержимого мелким кеглем. Поэтому
тот же zoom применяется к каждому гостю — при подключении, на его `did-finish-load` и при
смене настройки. E2e сравнивает `innerWidth` гостя с шириной его бокса у хоста.

Пинч и Ctrl+колёсико над диалогами прибиты `setVisualZoomLevelLimits(1, 1)`, иначе
масштаб уезжал бы мимо настройки.

**Последствия.** «100 %» камеры теперь означает 100 % внутри текущего масштаба
интерфейса, как в VS Code и Figma, а не «1 мировой пиксель = 1 физический». Chromium
запоминает zoom-уровень по origin внутри сессии, поэтому при смене масштаба живым гостям
он переназначается явно.

## ADR-020. Нода-картинка повторяет пропорции картинки

**Контекст.** Картинка лежала в произвольной рамке с `object-fit: contain` — вокруг поля,
а тяга за угол меняла рамку, а не картинку.

**Решение.** Натуральный размер спрашиваем у main (`nativeImage`), а не у DOM: у уже
раскодированной картинки событие `load` успевает пройти мимо обработчика React. При
загрузке ноды высота подгоняется под пропорцию (через `mutateSilent`, мимо истории), при
вставке и перетаскивании размер сразу считается от натурального (ширина не больше 800 —
иначе скриншот с 4K занимает весь холст). В оверлее у картинки остаются только четыре
угловые ручки, пропорция при ресайзе берётся из самой картинки, а не из текущей рамки.
`Shift` по-прежнему отключает пропорцию, если нужно растянуть намеренно.

**Последствия.** Рамка всегда по картинке, угол тянет саму картинку. Цена: при первом
открытии канваса с картинкой нестандартной высоты документ помечается изменённым —
высота подгоняется один раз и сохраняется.

## ADR-021. Отладочные запуски приложения — только со своим `--user-data-dir`

**Контекст.** Скрипт, снимавший скриншот, запускал приложение без отдельного
`--user-data-dir`. Приложение записало в настройки владельца `canvasPath`, указывающий на
временную папку в `/tmp`, и он несколько минут работал в ней, не зная об этом. Содержимое
пришлось переносить руками; после чистки `/tmp` оно бы пропало.

**Решение.** Любой запуск приложения из скриптов и тестов обязан получать собственный
`--user-data-dir` (в e2e это уже делает `tests/e2e/helpers.ts`). Настройки и канвас
владельца скрипты не трогают.

**Последствия.** Правило простое и проверяемое глазами в любом новом скрипте. Скриншоты
для README снимает `scripts/dev/shots.mjs` — он это правило соблюдает.

## ADR-022. Стороны связей подбираются по расположению нод

**Контекст.** JSON Canvas хранит у связи `fromSide`/`toSide`. Если записать их один раз,
то стоит поменять ноды местами — и стрелка продолжает выходить в ту же сторону, огибая обе
ноды. Владелец на это и пожаловался.

**Решение.** Настройка `edges.autoSides` (по умолчанию включена). При ней рисование
игнорирует записанные стороны и берёт те, что смотрят друг на друга, а подобранные стороны
отдельно дописываются в документ через `mutateSilent` — мимо истории и с задержкой 200 мс.
Дописывать обязательно: иначе файл разойдётся с картинкой и в Obsidian связь уйдёт не туда.

**Последствия.** Явно выбранная при создании сторона теперь не фиксируется навсегда —
за это отвечает выключатель в настройках. Перерисовка мгновенная (стороны считаются при
рендере), запись догоняет позже и попадает в то же сохранение, что и сдвиг нод, так что
лишних записей в файл нет.

## ADR-023. Веб-страницы по умолчанию не выгружаются

**Контекст.** Владелец: «веб страницы часто выгружаются когда уходят за экран, это не нужно,
их бы вообще стараться не выгружать никогда». Он до этого сам поднял `liveLimit` до 10,
`offscreenUnloadMs` до 60 с и опустил порог zoom до 0.1 — и это не помогло. Не помогло
потому, что менеджер жизненного цикла тут вообще ни при чём: ноду убивали два других,
более грубых пути.

1. **Отсечение по видимости.** `NodesLayer` оставлял в DOM только пересекающие viewport
   ноды. Ушла за край — React её размонтировал, `<webview>` удалился, гость умер.
2. **Упрощённый вид.** Ниже `nodes.lodZoomThreshold` (0.4) нода рисовалась заглушкой —
   то же самое размонтирование, только по zoom.
3. **Ключ по адресу.** `bodyKey` для веб-ноды возвращал `node.url`, а навигация внутри
   гостя этот `url` в документе обновляет. Каждый клик по ссылке внутри страницы менял
   ключ → React пересоздавал ноду → страница грузилась второй раз, история «назад»
   обнулялась. Померено тестом: сервер видел два GET на один переход.

**Решение.** Живая веб-нода — единственный владелец своего гостя, и размонтировать её
не вправе никто.

- `NodesLayer` получает `keepMounted` (живые веб-ноды) и не отсекает их по видимости
  и не упрощает по zoom.
- `bodyKey` больше не зависит от адреса. Адрес, изменившийся снаружи (ввод, undo,
  вставка), отрабатывается переходом `loadURL` у существующего гостя.
- Три порога выгрузки выключаются нулём (`liveLimit`, `web.lodZoomThreshold`,
  `web.offscreenUnloadMs`), и по умолчанию выключены все три.
- Снимок снимается **заранее**, пока нода на экране: у гостя за краем окна кадра может
  не быть вовсе, и `capturePage` там не возвращается никогда — выгрузка вставала в
  `await` намертво. Теперь картинка обновляется раз в 15 с у живых видимых нод, а ожидание
  перед выгрузкой ограничено по времени: снимок необязателен, решение выгрузить —
  обязательно.

**Последствия.** Раз увиденная страница живёт до закрытия приложения: память растёт с
числом открытых нод, и на десятке тяжёлых сайтов это заметно — лимит остался в настройках
ровно для этого. Ни разу не показанная нода гостя не поднимает, иначе открытие канваса
сразу будило бы все — она и после перезапуска показывает снятый заранее снимок, пока до
неё не долистаешь.

## ADR-024. Объект веб-рантайма обязан быть стабильным

**Контекст.** Владелец: «удаляю один браузер — перезагружается страница на всех
остальных». Так и было. `useWebLifecycle` отдавал наружу объект `runtime` через
`useMemo(..., [liveIds, …])`, то есть новую ссылку на любое изменение набора живых нод.
А эффект в `WebNodeView`, который создаёт `<webview>`, держал `runtime` в зависимостях.
Дальше арифметика простая: удалили ноду → пересчёт жизненного цикла → другой `liveIds` →
другой `runtime` → у каждой веб-ноды отработал cleanup `el.remove()` и гость поднялся
заново. Тест на своём сервере показал три запроса одной страницы вместо одного — причём
два из них ещё до всякого удаления, просто на старте.

**Решение.** `runtime` создаётся ровно один раз (`useRef`), методы читают refs. Живость
переехала в свой контекст `WebLiveContext`, который меняться обязан — на нём и держится
реактивность. `isLive` из рантайма убран: один источник правды.

**Последствия.** Всё, что попадает в зависимости эффекта, поднимающего гостя, теперь
обязано быть стабильным — это не стилистика, это единственное, что отделяет от
перезагрузки всех страниц разом. В DOM `<webview>` по той же причине нельзя переставлять:
любое перемещение элемента убивает гостя. Порядок рендера нод пока не тронут — z-order
всё ещё пересоздаёт гостей, это отдельная задача.

## ADR-025. Ctrl+колесо над страницей масштабирует холст

**Контекст.** Нода активна, страница получила фокус — и Ctrl+колесо начинает менять
масштаб самой страницы. Владельцу нужно обратное: масштаб холста.

**Три тупика подряд, и все по одной причине — вера в API вместо проверки.** Сначала взял
у гостя `input-event`: колесо приходит без дельты и без координат. Потом `zoom-changed`,
описанный в документации ровно под этот жест, — под синтетическим вводом он не приходил,
и я объявил его нерабочим (вывод был необоснованный: синтетика Playwright идёт мимо
настоящего пути). Потом придумал поднимать щит на время удержания `Ctrl` — заработало на
тестах и «иногда» у владельца, потому что механика по устройству гоночная: между нажатием
клавиши и появлением щита есть окно, и первый тик колеса в него попадает.

**Решение — идея владельца: не удержание, а режим.** Он у ноды и так есть: двойной клик
отдаёт мышь странице, `Esc` возвращает холсту. Пока мышь у холста, над страницей висит
прозрачный щит, и `Ctrl`+колесо обрабатывается **тем же кодом, что и на любой другой части
холста** — настоящая дельта, настоящий курсор, никаких исключений для гостя. Переключение
явное и мгновенное, гонке взяться негде.

Вся машинерия вокруг удержания `Ctrl` (IPC, контекст, слушатели на снятие залипшего щита,
«принудительный зум») удалена: работающий режим её не требует.

**Последствия.** Чтобы подвигать холст над страницей, надо выйти из неё `Esc` — зато
результат предсказуем. Масштаб самой страницы по-прежнему держит `zoom-changed` →
`applyScale`: им распоряжается только UI-скейл.

**Как это проверяется.** Тест бьёт по приложению **настоящим вводом X11 через `xdotool`**,
а не синтетикой Playwright: десять жестов подряд обязаны сработать все десять. Именно
синтетика позволила мне дважды объявить рабочим то, что не работало.

## ADR-026. Терминал: PTY в main, xterm в renderer, нода — текстовая

**Контекст.** Владелец хочет виджет терминала на холсте, по аналогии с веб-страницей.

**Почему PTY, а не пайп.** `child_process` с пайпами даёт поток байт и ничего больше:
ни цветов, ни `vim`, ни `htop`, ни Ctrl+C, ни размера окна. Всё это — псевдотерминал,
то есть нативный `node-pty`. Проверено спайком до написания фичи: настоящий `zsh`,
ANSI-последовательности на месте.

**Как лежит в файле.** Своего типа для терминала в JSON Canvas нет, а выдумывать —
значит терять совместимость, которую мы проверяем тестами. Поэтому это обычная нода
`type: "text"` с пометкой в `x-cnv`:

```json
{"id":"…","type":"text","text":"`терминал: zsh`","x-cnv":{"terminal":{"cwd":"/tmp"}}}
```

Obsidian покажет карточку с подписью и сохранит неизвестное поле как есть. `nodeKind`
смотрит на пометку и отдаёт вид `terminal`.

**Что переживает перезапуск.** Только рабочая папка. Процесс — нет, и не должен: держать
его дольше приложения значит писать свой tmux. Про свой `cd` шелл никому не сообщает,
поэтому папку main опрашивает у ядра через `/proc/<pid>/cwd` раз в 2 секунды и шлёт в
документ мимо истории, когда она изменилась.

**Упаковка.** Нативный `.node` из asar не грузится, поэтому `node-pty` в `asarUnpack`.
`npmRebuild` у нас выключен, значит модуль собирается под Electron руками —
`npm run rebuild:native`. Что собранное приложение действительно поднимает шелл, а не
только dev-сборка, проверено запуском `release/linux-unpacked`.

**Последствия.** У проекта появилась нативная зависимость: после `npm install` и после
смены версии Electron нужен `npm run rebuild:native`, иначе терминал не поднимется.
